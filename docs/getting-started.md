# 第一次使用 AgentCanvas

AgentCanvas 是本机画板：你在浏览器里画图、补充文字，再把当前画面和说明交给 Agent。推荐从 Agent 聊天中打开，这样画板会绑定当前项目和聊天。

## 安装后先做什么

需要 Windows 10/11 x64、Windows PowerShell 5.1 和已加入 PATH 的 Node.js 20+。安装包不含 Node。运行安装器时可选安装 Skill；已有或被你修改过的技能会保留，升级后可请 Agent 重新读取当前技能。安装后重开终端和 Agent 会话，运行 `agent-canvas --version` 检查命令可用。

便携包解压后可运行根目录 `agent-canvas.cmd`；不自动加入 PATH。只双击 `Start AgentCanvas.cmd` 会打开页面，不会让任何 Agent 自动开始等待。需要协作时，请在支持 Skill 和本地命令的 Agent 工具中加载包内 `skills/agent-canvas/SKILL.md`，并使用 CLI 的完整路径。

## 三步开始协作

1. 在准备处理任务的 Agent 聊天里说：**“打开这个项目的画板，我要画点东西。”** 如果当前聊天不在目标目录，同时告诉它项目路径。
2. Agent 打开画板，告诉你画板已打开、正在等待，默认最多 **120 秒**。在浏览器画图，并在右侧填写希望 Agent 做什么，例如“按这个草图设计页面”。
3. 点击右侧 **“发送当前画板”**（也可按 Ctrl+Enter）。看发送结果，再回原聊天查看 Agent 的处理回复。

每次发送的是当时的画面和文字说明；发送后继续编辑，不会自动把后续修改追加进上一次提交。收到内容也不等于任务已完成。

## 看状态决定下一步

| 显示或模式 | 意味着什么 | 你该怎么做 |
|---|---|---|
| **Agent 正在等待** | 当前有接收调用在等待这张画板 | 点击“发送当前画板”。发送成功后，等待中的 Agent 就能收到内容并继续处理。 |
| **未连接，发送后进入待处理箱** | 当前没有接收调用；可能只打开了页面，或120秒等待已结束 | 可以继续画并发送。确认保存成功后，回到**打开这张画板的原聊天**，提醒 Agent 领取。 |
| **已保存到待处理箱，Agent 尚未读取** | 内容已保存，尚未被领取 | 不必重复发送。把下方话术发给原聊天，让 Agent 从这张画板领取。 |
| **已发送，Agent 正在处理** | 内容已被领取 | 等待原聊天回复；这不是“已完成”。 |
| **已确认完成**（可靠性详情） | Agent 已回报这次提交处理完成 | 查看原聊天里的结果；有新需求再编辑、发送。 |
| 服务不可达、保存失败或发送失败 | 不能确认本次内容已可靠保存或交付 | 保留页面，必要时“导出当前副本”，让 Agent 检查服务并核对提交结果。 |

状态会定期刷新；以发送后的结果和原聊天回复为准。即使发送前显示等待，也可能恰好遇到等待结束，此时内容会留在待处理箱供补领。

## 未连接时，复制这句话回原聊天

如果原聊天还记得刚才的画板：

> 我已在刚才的画板点击发送，请领取这张画板待处理箱里的提交并继续处理。

如果需要明确告诉 Agent 去哪里找：

> 我已发送画板内容。请从项目「项目完整路径」、画板「完整画板ID」的待处理箱领取提交；使用 agent-canvas receive --timeout 0，不要新建画板。

把两个占位内容换成实际值：项目路径在右侧工作区下方；完整画板ID可展开 **“连接与可靠性 → 诊断详情”** 查看，也可从 Agent 打开画板时的回复获取。不要把内容版本号或简短聊天标识当作画板ID。回到原聊天最容易保留绑定和任务上下文；换聊天时先说明要继续哪张画板，不要猜测其他聊天的内容。

补领对应的命令如下（通常由 Agent 执行，你不必手动运行）：

```powershell
agent-canvas receive --project "<项目完整路径>" --board <完整画板ID> --timeout 0
```

如果还没画完，可以说 **“继续等这张画板120秒，我画完就发送。”** Agent 再调用 `receive --timeout 120`。默认流程不会无限循环等待；聊天回合结束后，网页不能自动唤醒 Agent。

## 各种使用方式

| 你想做什么 | 对 Agent 说什么 | 效果 |
|---|---|---|
| 边画边交给 Agent | 打开画板，我要画点东西 | 打开 → 明确提醒 → 等待最多120秒，有提交提前返回。 |
| 慢慢画，稍后再处理 | 只打开画板，不用等 | 页面可用；发送成功后先保存在待处理箱，之后回原聊天提醒领取。 |
| 已发送，马上补领 | 领取刚才画板的提交 | 立即检查并领取已有提交，不再等待120秒。 |
| 只检查情况 | 看看画板状态，不要领取 | 只读检查，不拿走待处理任务。 |

CLI 返回的 `receiveMode: poll` 表示接收通过请求读取；`receive --timeout 120` 仍然会等待，内部自动续接短请求。它不表示后台永久在线。旧 `wait/inbox` 用于旧项目画布；DSH 内嵌模式由宿主管理，不与上述独立画板混用。

项目、画板与聊天各自绑定；多聊天工作时检查右侧“当前绑定”和项目路径，避免把内容发给错误目标。本地画板数据不随安装包上传；当 Agent 调用模型处理内容时，网络及数据处理由所用 Agent 工具决定。
