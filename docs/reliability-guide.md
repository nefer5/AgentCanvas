# 0.2.2 本地画板使用与恢复

首次使用请先看[中文入门指南](getting-started.md)：包括正在等待、未连接、提交待领取时的操作，以及回原聊天补领的话术。

独立画板使用稳定 boardId，与“项目 + 工具/聊天身份”绑定。旧项目画布仍由首页项目选择器打开；新CLI不会迁移或覆盖旧内容。DSH内嵌入口继续由宿主拥有数据，本页历史不操作DSH记录。

## Agent快速流程

### 先匹配用户意图

| 用户要求 | 正常动作 |
|---|---|
| 打开画板、我要画点东西 | open成功后先发可见提醒，再receive --timeout 120；已有绑定则复用 |
| 明确只打开/不等待，或只打开并检查状态 | open；按需status，不进入receive |
| 看有没有提交/检查连接 | status，只读，不领取，不等待 |
| 领取已经提交的内容 | receive --timeout 0，立即检查 |
| 等待用户的新提交 | receive --timeout 120，有界等待 |

正常打开不需要先查版本、doctor、遍历目录或调用浏览器自动化。open会校验真实目录、检查/启动本地服务、注册项目、恢复绑定并请求浏览器可见握手。项目目录应使用用户指定值，否则用当前真实工作目录；只有用户明确要求新建目录时才创建，不把“允许创建”当作必须预检创建。

### 第一次打开

优先用宿主已经提供的真实聊天ID，格式为`工具名:聊天ID`。没有ID时，直接在执行open的同一次shell里实际生成一次UUID，不枚举环境变量或会话文件，不用目录、标题、固定字符串冒充聊天身份。

下面是**PowerShell、新聊天首次、宿主没有提供ID、用户明确只要求打开并检查状态**的模板。OpenCode的工具名为opencode；其他工具替换成自己的名称。

```powershell
$p = "<项目目录>"; $c = "opencode:$([guid]::NewGuid())"
$r = agent-canvas open --project $p --conversation $c --name "<画板名称>"
$r
if ($LASTEXITCODE -eq 0) { agent-canvas status --project $p --board (($r | ConvertFrom-Json).boardId) }
```

用户明确只打开、不等待时可省略最后一行。普通“打开画板，我要画点东西”仍按下文先提醒再等待。给宿主shell至少30秒的执行时间；此数值是超时上限，不是要求等待30秒。Bash等其他shell需使用等价语法或显式调用PowerShell，不能直接混用语法。不把npm脚本交给Start-Process，不另起开发服务器。

### 同聊天继续使用

保存open返回的完整binding与boardId到当前聊天上下文。下次重开用原binding，不能重新生成UUID；不同shell工具调用之间也不能假定临时变量仍存在。

```powershell
agent-canvas open --project "<项目目录>" --conversation "<上次返回的完整binding>" --name "<画板名称>"
agent-canvas status --project "<项目目录>" --board <上次返回的boardId>
```

相同项目与聊天恢复同一画板，不同聊天各自独立。若需要显式采用手动画板，只对用户指定且尚未绑定其他聊天的画板添加`--board`；不自动转交绑定。

### 结果如何解释

- opened且pageLoaded/pageVisible都为true：页面已加载并确认可见。成功时简短回复打开结果、画板ID和检查结果，不重复讲解整个流程。
- receiverReachable或receiverOnline为false不能当作页面加载失败。可见页面与Agent接收通道是不同状态；用status查看当前状态，不为接收离线重复打开窗口。
- browser-unconfirmed：已请求打开，但可见性尚未确认，不能当成功。保留原项目和聊天身份，根据错误和doctor结果诊断，再重试原绑定。
- 其他错误：按code/message处理，不换项目、不占用其他聊天画板、不擅自停止共享服务或使用Repair。

### 先向用户提醒，再等待提交

open确认可见后，Agent应先发出用户能看到的中文进度消息：“画板已打开，请画完后点击提交。我现在开始等待，本次最多120秒。”随后才执行receive，不要把提醒留到120秒之后，也不要把open和receive塞进一次阻塞shell。此时不应结束Agent回合。

```powershell
agent-canvas receive --project "<项目目录>" --board <boardId> --timeout 120
```

receive省略timeout时也默认120秒，CLI允许0–120秒。宿主工具超时至少150秒，建议180秒。服务协议仍是单请求最多20秒，CLI自动使用相同请求身份连续等待，最后只返回一个结果；已有服务无需为此重启。传输失败会保留重试身份，不把失败冒充empty。

submitted会在提交到达时立即返回；empty说明这次等待已结束，应明确告诉用户当前不再等待，不承诺回合结束后自动唤醒。busy/CLIENT_BUSY时不新建并发接收者。

### 接收与完成工作

```powershell
agent-canvas receive --project "<项目目录>" --board <boardId> --timeout 0
agent-canvas renew <submissionId> --project "<项目目录>" --board <boardId>
agent-canvas release <submissionId> --project "<项目目录>" --board <boardId>
agent-canvas complete <submissionId> --project "<项目目录>" --board <boardId>
```

只查状态时不调用receive。默认打开后先提醒，再等待120秒；用户明确只打开或不等待时跳过。需要立即领取已有提交时用timeout 0。empty是正常的等待结束结果。submitted表示已领取，先读取返回场景/预览并实际完成用户工作，验证后才能complete。处理超过两分钟要在租约到期前renew；尚未完成而需交还时release。重试可能拿到同一提交，用submissionId避免重复副作用，不能承诺外部工作恰好执行一次。

回合结束后不会自动唤醒Agent；用户提交会保留，下次继续本聊天领取。打开画板不代表后台一直在线。接收凭据由CLI管理，不打印或上传connections目录，不通过枚举模型认证或宿主环境变量寻找聊天ID。

旧版inbox有领取副作用，不能用于只读诊断；旧项目画布仅在用户明确继续旧流程时使用wait/inbox。DSH内嵌仍按其宿主流程，不替换为独立CLI。

## 协作界面

桌面端使用停靠右栏，画布为协作面板让出空间，收起后保留64px窄栏；平板和手机使用可展开浮层，避开原生绘图工具栏。右栏按工作区、真实画面概览、说明输入、保存/历史及可靠性管理分组。概览只显示元素数和版本，不模拟AI诊断。绑定在右上角醒目显示工具与简短会话标识，无绑定时显示“未绑定聊天”；后台确认绑定变化后同步刷新，完整值保留在悬停提示和诊断详情。独立画板以只读卡片显示“所属工作区”，使用“打开其他画板”浏览全部项目，不直接修改当前画板归属。内容版本只表示本画板内的保存序号，不是画板ID。

浅色卡片、统一线性图标及低饱和绿状态色用于界面层；不会重画用户图形、改变画板背景或加入参考图里的未实现动作。

## 可靠性面板

服务状态、接收状态、画板保存和编辑窗口分别显示。后台/休眠后状态待刷新；连续检查失败显示暂时不可达，不能据此断言进程已退出。服务实例重启后仍通过版本比较保存，冲突不会覆盖磁盘内容。

保存失败时保留页面，使用“导出当前副本”获得.excalidraw文件。版本冲突需要先导出，再重新加载/另存；本版本没有自动合并。浏览器副本按画板与窗口隔离，避免多个页面覆盖同一个恢复键。

网页不能调用已经失效的同一个HTTP服务来重启自己。需要恢复时运行本机AgentCanvas启动器；端口不健康时默认不杀进程。维护者核对其他聊天后才使用start-excalidraw.ps1 -Repair。Windows启动器用命名Mutex串行启动，服务以本机命名管道阻止同一注册表目录的第二实例；仍只在127.0.0.1监听HTTP。

## 历史与清理

“画板历史”可切换当前/全部项目，搜索名称或聊天，分页查看活跃、归档及回收站。图形预览为几何缩略图，不是完整文字/笔迹渲染。列表只统计当前页可访问画板的占用，目录不可用时显示未知并禁止操作。

移入回收站前提供数量/占用预览，执行时重新核对画板版本与保护条件。当前窗口、其他活跃窗口、失联窗口、收藏、未完成任务和冲突副本保护。失联窗口不会因超时被默认为已关闭；确认相关页面关闭或副本已保存后可明确解除失联保护。迟到的旧页面不能把已回收画板重新创建。

画板整体的回收仍是可恢复移动，不等于释放磁盘空间。归档只整理列表。自动历史快照则采用下述有界存储，不再把超额版本搬到另一个目录继续堆积。

### 自动快照保留上限

- 当前内容采用两个固定文件交替提交，再原子更新指针；兼容镜像继续保留。每次实际修改都可保存，相同内容不写新版本。
- 每张画板的自动历史最多20份，合计64 MiB，至少间隔60秒才保留一次。达到数量或容量上限后复用旧槽位，淘汰最旧的自动历史；不创建无限增长的回收目录。
- 冲突恢复副本另保留最多3份、合计64 MiB；当前编辑器和浏览器未保存草稿不会因历史轮换而清空。重要冲突应及时导出处理，不能无限期依赖自动恢复副本。
- 当前内容不计入历史额度，单份保存文件上限32 MiB。两份当前槽位和兼容镜像是固定数量，与编辑次数无关。
- 显式提交给Agent的快照与附件属于任务数据，保持独立，不随自动历史淘汰。画板回收保护仍检查未完成任务和冲突记录。
- “自动快照与空间 → 查看占用与保留策略”显示实际占用和限额。旧的“保留50份再搬到version-trash”操作已停用；只保留旧整理中断的恢复兼容代码。
- 内容版本号仍随实际保存递增；版本号1000不表示磁盘上有1000份文件。旧快照被淘汰后不再保证任意旧版本可恢复。

旧格式1/2仍可读取；当前格式3由0.2.1及以后版本读取。升级迁移保留内容与版本号，不重置画板身份。

## 数据位置与保留

- 新画板：项目 `.agent-canvas/boards/<boardId>/`；回收目录 `.agent-canvas/board-trash/<boardId>/`。
- 当前内容在current/scene-a.excalidraw与scene-b.excalidraw中交替保存；自动历史及冲突副本在snapshots固定槽位。旧versions仅用于兼容读取和遗留恢复记录。不可变提交、预览、jobs.json与presence.json归属于画板。
- 本机索引：`%LOCALAPPDATA%/ExcalidrawAgentBridge/boards.json`，含绑定接收凭据，不能上传。
- CLI凭据：项目 `.agent-canvas/connections/<boardId>.json`，由CLI使用，不输出到URL/stdout。
- 旧版current/inbox/processed数据原位保留，安装/升级不打包任何用户数据。

当前不提供系统回收站清空或自动唤醒宿主的适配器。发布验收方法见[发布手册](releasing.md)。
