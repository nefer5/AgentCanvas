# Agent 画板

## 按用户意图选择动作

| 用户要做什么 | 执行动作 |
|---|---|
| 打开画板、我要画点东西 | open → 先发用户可见提醒 → receive --timeout 120；已有绑定则复用 |
| 明确只打开、不等待，或只打开并查状态 | open；按需status，不receive |
| 看状态或有没有提交 | status，不领取、不等待 |
| 领取已有提交 | receive --timeout 0 |
| 等待用户新提交 | receive --timeout 120 |

## 打开路径

项目使用用户指定目录，否则用当前工作目录。直接交给open校验，不先遍历目录、检查版本或调用doctor。只有用户明确要求新建目录时才合并创建；仅“允许创建”不代表必须先检查创建。

聊天已有binding时使用原值，不依赖shell变量跨调用保存。首次优先使用宿主提供的真实聊天ID；未提供则在打开命令内用UUID生成器生成，不查环境/会话文件、不编造常量身份。

PowerShell首次打开的模板（工具名替换为当前宿主，OpenCode为opencode）：

```powershell
$p = "<项目目录>"; $c = "<工具名>:$([guid]::NewGuid())"
$r = agent-canvas open --project $p --conversation $c --name "<画板名称>"
$r
```

已有身份则把$c填为原binding。open的工具超时至少30秒。不用浏览器自动化、额外后台进程或Start-Process包装npm命令；不要把open和receive合并成一次阻塞shell，否则用户会等到接收结束才看到提醒。

## 先提醒用户，再等待

1. 只有opened且pageLoaded/pageVisible都为true才确认可见。记住binding和boardId。
2. **先发一条用户可见的中文进度消息**：“画板已打开，请画完后点击‘发送当前画板’。我现在开始等待，最多120秒；显示‘Agent 正在等待’时，发送后我就能收到。若显示‘未连接’，发送成功后内容会留在待处理箱，请回到本聊天说‘领取刚才画板的提交’。”附上项目目录和完整boardId，方便找回。不是写在思考或日志里，也不要用最终回复结束回合。
3. 随即调用下面命令，宿主工具超时设为至少150秒，建议180秒。CLI内部续接等待，不让模型每20秒重新决定是否继续。

```powershell
agent-canvas receive --project "<目录>" --board <boardId> --timeout 120
```

默认打开流程必须执行这一步。只有用户明确说“只打开”“不用等”或“只查状态”时才跳过；已有内容立即领取仍可用timeout 0。

submitted表示已收到本次提交，继续处理。empty表示本次120秒等待结束，要明确告知已停止等待：“本次等待已结束，你可以继续画并发送；发送成功后回到本聊天说‘领取刚才画板的提交’，我会从这个项目、这张画板的待处理箱获取。”保留并使用原项目目录和boardId，以receive --timeout 0补领；不要要求用户重画、重发或另建画板。不谎称后台常驻，也不无限自动重试。busy/CLIENT_BUSY说明已有接收或处理活动，不另起并发领取。工具超时或断线不等于用户没有提交，保留绑定并检查状态后再恢复。

## 向首次使用者解释模式

用户问如何使用、模式或未连接时，用以下含义解释，不只报poll/wait术语：

| 页面状态或操作方式 | 用户怎么用、会发生什么 |
|---|---|
| Agent 正在等待（默认打开后等待120秒） | 画图，可填写文字说明，点击“发送当前画板”；提交成功后，正在等待的Agent能收到并继续处理。收到不等于已完成。 |
| 未连接，发送后进入待处理箱（只打开或等待结束） | 仍可画图并发送；确认显示已保存后，回到**打开这张画板的原聊天**提醒Agent领取。页面开着不代表Agent一直在线，不会自动唤醒已结束的聊天。 |
| 已保存到待处理箱，Agent 尚未读取 | 不必重复发送。在原聊天说：“请领取项目<目录>、画板<完整boardId>的提交。”Agent从该画板待处理箱receive --timeout 0领取；若用户要继续等，再用120。 |
| 已发送，Agent 正在处理 | 已领取，等原聊天回复；不要重复领取或把它说成工作完成。 |
| 服务不可达或发送失败 | 不保证内容已入待处理箱。保留页面/导出副本，先检查恢复，再核对发送结果。 |

若原聊天没有保留上下文，让用户提供右侧项目路径与“连接与可靠性 → 诊断详情”中的画板ID，不凭名称猜其他会话。只查状态不领取；旧wait/inbox仅用于明确的旧项目画布，DSH内嵌按宿主流程，不能混用board领取命令。

receiverReachable/receiverOnline为false不等于页面失败，不因此重开画板。回合结束后没有自动唤醒保证；保持等待的这一次调用才会在提交到达时返回。

后续命令均带`--project "<目录>" --board <boardId>`。submitted才算领取：先读场景/预览并实际完成工作，验证后才能`agent-canvas complete <submissionId>`；长于两分钟先renew，未完成交还用release（参数相同），以submissionId避免重复副作用。领取凭据由CLI保管，不打印或上传connections。

browser-unconfirmed不能声称可见；错误按code/message处理，保留原绑定，必要时doctor。不自动占用其他聊天或杀共享服务/Repair，不绕过历史保护、不清浏览器数据。旧inbox会领取，仅明确继续旧画布才用；DSH嵌入由宿主管理。自动历史20份/64 MiB/60秒，冲突3份/64 MiB，显式提交独立保留。
